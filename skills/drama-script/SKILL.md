# 专业短剧剧本创作

以编剧、导演和制片统筹的共同视角工作。把输入发展为完整影片制作链的第一份生产文档，而不是只写故事梗概。

## 使用资料

开始创作前按任务需要读取：

- 爽剧、强冲突、复仇或逆袭题材：读取 [爽点模型](references/satisfaction-model.md)。
- 需要确定题材套路、受众和情绪曲线：读取 [题材模式](references/theme-patterns.md)。
- 需要设计开篇、单集节奏和连续剧结构：读取 [爆款结构分析](references/template-analysis.md)。

应用集成可预加载以上资料；独立使用时只读取与本次题材有关的内容。

## 创作流程

### 1. 理解创作意图

从用户输入中判断：

- 核心人物、欲望、阻力和代价；
- 世界、时代、受众和画面类型；
- 原创或改编，以及必须保留的设定；
- 计划集数、单集体量和是否必须完结；
- 情绪基调及主要观看满足：爽、甜、虐、悬疑、喜剧或混合。

用户未明确的次要信息应作合理创作决策，不因缺少表单字段停止工作。不得擅自改变用户明确指定的角色关系、结局方向或世界规则。

### 2. 建立故事引擎

明确写作前的内部决策：

1. 主角最想得到什么；
2. 谁或什么持续阻止主角；
3. 主角失败会失去什么；
4. 观众比剧中人多知道什么；
5. 哪个事件让故事不可逆；
6. 最终高潮如何兑现开篇承诺。

对爽剧使用“情绪锚定 → 烈度放大 → 信息差 → 价值反转”。其他题材也必须有可追踪的冲突升级和因果链，不能靠巧合连续推进。

### 3. 规划全剧与分集

- 前 20%：快速建立人物处境、核心冲突和观看承诺。
- 中 60%：扩大代价，推动关系变化，连续兑现局部高潮并制造新问题。
- 后 20%：集中回收伏笔，完成终极选择与高潮，给出与要求一致的结局。
- 首集开头尽快出现冲突、悬念或反转。
- 非结局集结尾留下由本集因果自然产生的钩子。
- 结局集完整收尾，不添加下一集预告；仅在用户要求完结时使用【本剧终】。
- 场次变化必须对应地点或时间变化，不拆分同一连续场景凑数量。

若用户给出单集目标时长，先做可表演时长预算：自然中文对白约每秒 3–4 个汉字；短反应约 1–2 秒，完整动作约 2–4 秒，移动、停顿和转场另计。逐段累计后预留约 10% 节奏余量。60 秒短集通常只容纳 2–4 场、一个主要冲突变化；不得以“约一分钟”为名写出数分钟内容。

### 4. 写可拍摄剧本

剧本只写可见或可听的信息：具体动作、表情变化、位置移动、对白、画外音、关键音效和环境事实。

每场使用以下格式：

```text
[1] 内 总裁办公室 日
人物：林夏、周屿
△ 林夏把辞职信推到桌面中央，右手仍压在纸角。
林夏（冷声）：「从今天起，我们两清。」
```

强制规则：

- 场景标注使用 `[数字] 内/外 地点 晨/日/昏/夜`。
- `人物：` 列出本场所有在场的命名角色，包括没有台词的人。
- 一个 `△` 行聚焦一个主要动作或清楚的画面事实。
- 不写“内心痛苦”“气场全开”“美得不可方物”等无法直接拍摄的抽象描述。
- 不在剧本阶段写特写、推拉摇移等镜头指令；镜头语言交给分镜 Skill。
- 对白使用中文引号 `「」`；表演提示只写简短情绪、语气或动作，最多 10 字。
- 每句对白必须推进冲突、关系或信息，删除解释性废话。
- 角色命名和称呼保持全剧一致，言行符合身份、时代和既有经历。

### 5. 建立影视资产档案

在剧本之后输出角色、场景和关键道具，供图片生成与分镜引用。

- 角色形象是纯净主体：完整外貌、发型、服装和站姿，不带场景、其他人物、剧情动作或关键道具。
- 场景是无人空镜：描述机位、空间、材质、陈设、天气、时段、色调和光线，不出现人物与剧情动作。
- 道具是独立物件：只提取承担剧情信息或需跨镜头保持一致的物品，描述材质、颜色、形状、尺寸和识别细节。
- 名称短且稳定。角色和形象名不使用连字符；场景的明显时段或天气变体使用下划线区分。
- 同一角色有显著换装或身份阶段时拆成多个 `looks`，否则只建“默认形象”。
- 同一人物的不同时期若不会同时出场，归为同一角色的不同 `looks`；未来自己、克隆体、替身等版本若会同场互动或需要独立对白标签，必须建立可区分的独立角色（如“林夏”“未来林夏”），避免分镜引用歧义。

## 输出契约

默认只输出合法 JSON，不加 Markdown 代码围栏或解释文字。若调用方给出更严格的 JSON Schema，以调用方 Schema 为准，但不得丢失剧本、角色、场景、道具四类核心产物。

```json
{
  "summary": {
    "title": "剧名",
    "protagonist": "主角姓名与身份",
    "genre": "题材或受众类型",
    "synopsis": "客观讲清起因、发展、高潮与结局的剧情梗概",
    "background": "故事背景",
    "setting": "关键世界设定",
    "oneSentence": "突出人物、冲突和核心看点的引流文案"
  },
  "episodes": [
    { "episodeNumber": 1, "title": "本集标题", "content": "完整可拍摄剧本" }
  ],
  "characters": [
    {
      "name": "角色名",
      "role": "protagonist",
      "gender": "female",
      "introduction": "身份、动机、内在冲突、关键经历和性格",
      "voiceDescription": "年龄感、音调、音色、发音、气息和整体印象",
      "looks": [
        { "name": "默认形象", "episodes": [1], "description": "可直接生成纯净角色参考图的完整视觉描述" }
      ]
    }
  ],
  "scenes": [
    { "name": "场景名_夜晚", "episodes": [1], "description": "可直接生成无人场景参考图的视觉描述" }
  ],
  "props": [
    { "name": "关键道具", "category": "item", "episodes": [1], "description": "可直接生成独立物件参考图的视觉描述" }
  ]
}
```

枚举约束：

- `role`：`protagonist`、`antagonist`、`supporting`、`minor`。
- `gender`：`male`、`female`、`other`、`unknown`。
- `category`：`weapon`、`vehicle`、`clothing`、`accessory`、`item`。

## 交付前检查

- 分集数量与用户要求完全一致，集号从 1 连续递增。
- 故事有明确开端、升级、高潮与符合要求的结局。
- 每场地点、时间、人物和动作均可执行，没有小说式心理描写。
- 连续相同地点和时间没有被拆成多个场次。
- 人名、身份、能力、称呼、道具与时间线前后一致。
- 角色、场景、道具完全解耦，`episodes` 与正文实际出现位置一致。
- JSON 可以直接解析，且没有输出契约之外的说明文字。
